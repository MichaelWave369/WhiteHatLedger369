# Release Guardian R6 · Advisory evidence policy

**R6 status:** A functioning, read-only, non-blocking release evidence evaluator for this repository. **It does not authorize, approve, or block production releases.**

## Inputs and boundaries

All files are fixed relative to the checked-out repository. No external target URLs, arbitrary code execution, developer tokens, private keys, or secrets are consumed.

1. `package.json`: hashed at report generation; matches Sentinel's declared source fingerprint.
2. `public/sentinel-report.json`: generated by R1's OSV check. Counts, source fingerprint, and freshness are validated.
3. `public/evidence-ledger.json`: independently checked signed R5 **synthetic fixture**. Its verification is displayed separately, NOT treated as production consent, remediation, or tested deployment.
4. `GITHUB_SHA`: optional CI context claim. **Not** a signed provenance attestation.

`public/guardian-report.json` is a generated **unsigned advisory**. Its checked-in placeholder is explicitly UNKNOWN until the Pages pipeline regenerates it. Neither the website nor the CI environment independently attests the integrity of the runner or its published report.

## Decision rule

Statuses are `PASS`, `FAIL`, `UNKNOWN`. For a set of required controls:

- If any control FAILS, overall **FAIL** (operator investigation required).
- Else, if any control is UNKNOWN, overall **UNKNOWN**.
- Only all required PASS produces overall **PASS**.
- Empty, invalid, or unexpected statuses produce **UNKNOWN**.

### Required production controls

| Control | R6 evidence | Status semantics |
| --- | --- | --- |
| Direct exact-version npm advisories | OSV.dev and matching manifest SHA-256, bounded 48h freshness, complete per-package rows | Narrow PASS if zero reported matches, FAIL if matches, otherwise UNKNOWN |
| Transitive dependency and SBOM | No independently verified lockfile/deployment dependency tree | Always UNKNOWN in R6 |
| Build and deployment attestation | GitHub workflow runs but no signed immutable artifact proof | Always UNKNOWN in R6 |
| Signed owner consent and scope | No owner-issued, independently trusted scope receipt | Always UNKNOWN in R6 |
| Real patch/retest evidence | R5 is synthetic, not a deployed repair | Always UNKNOWN in R6 |

Consequently an R6 release posture **cannot be PASS** until real independent evidence and a later policy upgrade are delivered. This is deliberate, not a defect.

A FAIL is a *policy-triggered triage state*, not proof that a live exploit exists. PASS on the advisory row only means OSV reported no matches in this narrow, fresh source-matched query. It does not certify the dependencies secure.

## Signed fixture is excluded

The valid signed R5 sample is scoped exclusively to `lab://whitehat369/evidence`. R6 checks its signature and hash chain via independent Node.js verifier, then displays that example separately. It cannot count towards real owner consent, live incident remediation, or target authorization.

## Lifecycle and verification

```sh
npm run test:guardian
npm run guardian:report
```

The Pages workflow: test unit suites → run Sentinel OSV lookups → generate Guardian advisory → build static web app → deploy. A previous source checkout contains only a placeholder file.

The CI workflow checks Guardian's policy test matrix but does **not** call external OSV or enforce Guardian findings as a blocking gate. GitHub Pages still deploys even when Guardian's assessment says FAIL or UNKNOWN. The UI includes a local-only policy toy panel; it has no connection to production controls.

## Known limitations and required next gate

R6 does not detect deployed vulnerabilities, verify installations, scan other repositories, authenticate the build machine, control an AI agent, or independently validate the report host. **Do not use R6 status to claim production readiness.**

Future work: lockfile/SBOM provenance, key custody and rotation, signed external trust anchor distribution, real consent receipts, append-only findings and retests, deploy attestation, and independent authorization review before transitioning to a blocking release gate.
